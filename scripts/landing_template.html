Why it isn't just "ask an AI about my code"

  • Grounded. tree-sitter maps the real files, functions and calls first. Claude may only describe things in that map — output naming a file, symbol or line that isn't in the upload is rejected and regenerated.
  • Plain English. Five-word titles, 25-word explanations, and arrows labelled with the data that actually moves.
  • Cheap on purpose. Static analysis does everything it can for free; prompt caching, batching and a content hash cache do the rest. You see a cost estimate first.
  • Your key, your bill. No accounts. The key stays on the server and never reaches the browser or the logs.
  • Never runs your code. Uploads are read as text and parsed.

Run the full app

The demos above are static snapshots. To analyse your own code you run the app locally — it needs its Python backend for unzipping, parsing and talking to Claude.

git clone https://github.com/Baharul0111/CodeFlow-Explorer.git
cd CodeFlow-Explorer
make install
make dev          # then open http://localhost:3000

No API key handy? LLM_MODE=mock runs the whole pipeline against a deterministic stand-in, exactly like these demos.
